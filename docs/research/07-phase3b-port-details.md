### Debt, measurement, retirement and tombstones

HealthPredictor's lower HP is `max(0,anchor - sum(max(0,assessment.amount-credited)))`, or null without anchor. Impact IDs deduplicate within both active and settled maps. Measured DAMAGE replaces the assessment and sets `serverSeenAt` once; later speculative duplicates cannot revise an incurred hit's basis. This is how the common reported-projectile/DAMAGE pair is charged once in either order. A settled matching ID returns without reopening debt. Identity ambiguity can still conservatively overcount: distinct unresolved reports are intentional separate assumptions; this is not proof of correspondence. Delivery tracks **local enqueue time**, not remote acceptance. `delivered(written)` sets the first writtenAt; `blocked` deletes observation bookkeeping but **retains loss**. Explicit HP snapshots update anchor/revision, with net downward delta as possible credit; no unused credit carries forward and healing supplies none. Credit is oldest insertion order first, only after `max(25,p99(RTT)/2)` since `writtenAt ?? serverSeenAt`. Existing credited amount is retained if a later measured assessment changes amount; remaining liability clamps at zero. [HP:89-148](https://github.com/DaAwesomePwner/realm-engine-client/blob/88a66b2155cddfe9c1bd086e58d408941dcef697/client/src/safety/HealthPredictor.ts#L89-L148)
