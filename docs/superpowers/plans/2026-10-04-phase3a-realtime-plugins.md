# RealmTool Phase 3a — Realtime plugins: Auto Nexus (server HP) + Auto Drink

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Auto Nexus (server-HP threshold) and Auto Drink run as realtime plugins. Each has a main-thread half (settings, commands, status) and a worker module that decides and writes ESCAPE / USEITEM beside the sockets, before the main thread sees the packet. Both are ported from realm-engine-client `88a66b2` with the FORK.md guarantees pinned by ported tests.

**Architecture:** Phase 1's worker-module surface (`src/transport/modules.ts`) gains the few hooks the source worker relies on: accepted server writes, narrow upstream backpressure, writer origin, shared per-session automation state, and validated batch configuration. Phase 2's plugin API gains a built-in-only `worker` capability: a typed channel between a plugin and its worker module, with module ids equal to plugin ids. Configuration is coalesced so the worker never sees a half-applied profile. The safety core (server-HP branches of `SafetyEngine`, `EscapeAttemptCoordinator`, `AutoEscapeReportGuard`) and the drink core (`AutoDrinkController`, `ClientGameClock`) are ported as pure classes with their tests. They are then wrapped in `plugins/auto-nexus/` and `plugins/auto-drink/`. Auto Drink's consumables come from a generated, build-stamped `data/catalogs/consumables.json`. The runtime never parses XML.

**Tech Stack:** Same as Phases 1–2 (Node ≥ 22.18 native TypeScript, Vitest 3). New **dev-only** dependency: `fast-xml-parser` (catalog generator in `tools/` only). No new runtime dependencies.

**Spec:** [`docs/design.md`](../../design.md) §2.1–2.3, §3 (behavior that must be preserved), §5 Phase 3a row. Port research: [`docs/research/06-phase3a-port-details.md`](../../research/06-phase3a-port-details.md), cited below as **R§n**. Source: realm-engine-client `88a66b2` (`REC` = a detached checkout at that commit).

## Global Constraints

- All Phase 1–2 constraints still apply:
  - `.ts` import specifiers, erasable syntax only (no enums, namespaces or constructor parameter properties);
  - `npm run check` green; Windows x64; listen only on 127.0.0.1;
  - RC4 keys only in `src/protocol/constants.ts`; never start `RotMG Exalt.exe` directly;
  - the game access token is never logged, persisted or stored beyond the call that uses it.
- Ported files keep the header `// Ported from realm-engine-client <path> @ 88a66b2 (MIT, see NOTICE).` (adapted files: `// Adapted from realm-engine-client <path> @ 88a66b2 (MIT, see NOTICE).`).
- **Time-critical decisions run only in worker modules.** ESCAPE and automatic USEITEM are decided and written by the worker. The main thread never decides on them, and nothing on that path waits on the main thread.
- Worker modules run in priority order **Auto Nexus = 0, Auto Drink = 10**. Module ids equal plugin ids: `auto-nexus`, `auto-drink`.
- **Server HP:** max HP is stat **0**, HP is stat **1**; never an "effective" or bonus-adjusted maximum. Threshold HP = `maxHp * thresholdPct / 100`, unrounded. A positive threshold triggers on `hp <= threshold`. **0% triggers only on an explicit server HP of 0.** Unknown HP or max HP never triggers.
- **Escape:** normal ESCAPE plus a server-authorized RECONNECT only. Initial write plus up to **4 retries**, **400 ms** apart, one write per advance, no catch-up bursts. The ESCAPE is written before plugins, observers or the main thread see the packet that triggered it.
- **Report guard:** after an **accepted automatic** escape, suppress exactly `PLAYERHIT`, `AOEACK`, `GROUNDDAMAGE`, `MOVE` (client direction). Check both at entry (after decryption) and at the final writer (before output RC4). Only a new upstream TCP generation releases it; a manual ESCAPE alone never arms it.
- **Collision HP is absent in 3a:** no `PreHitPrediction` setting, nothing saved for it, and the worker rejects any attempt to enable prediction. Messages say "server HP threshold only".
- **Auto Drink:** server stats 0/1/3/4 (max HP, HP, max MP, MP); no predicted healing; game time only from **accepted** MOVE/PONG/PLAYERSHOOT; disarmed by any escape for that TCP generation; its own USEITEM is never treated as a manual use.
- **Catalog:** `data/catalogs/consumables.json` is generated by `tools/gen-catalogs.ts` and stamped with the game's Unity `build-guid` from `RotMG Exalt_Data/boot.config`. The runtime validates it and never parses XML. `fast-xml-parser` is imported only under `tools/`.
- No Realm Engine DLL, native-health, telemetry, reaction-learning, recorder, dashboard or status-relay code is ported (R§1 "Defer to 3b; drop diagnostic code entirely").
- Phase 3a alone is **not releasable** (design §5: never ship Auto Nexus without Collision HP, Phase 3b).

## Review Focus

1. **The main thread is blocked (a slow plugin hook, GC) while server HP crosses the threshold:** ESCAPE is still written by the worker on that packet, and retries continue. Pinned in Task 8.
2. **A RECONNECT that is held, dropped by a plugin, or malformed:** it must not confirm the transfer, cancel Auto Nexus's attempt or release the report guard. Only an accepted, written RECONNECT does. Pinned in Tasks 1 and 6.
3. **A profile loads with settings for both plugins (startup or a later batch):** the worker never runs a packet against a half-applied mix of old and new settings; invalid configuration is rejected whole. Pinned in Tasks 1 and 2.
4. **Auto Drink and an escape race:** a rejected or manual Auto Nexus attempt still disarms Auto Drink for that generation, and Auto Drink's own USEITEM is never re-observed as a manual use. Pinned in Tasks 7 and 8.
5. **The catalog is missing, invalid, or from another game build:** Auto Drink loads with no consumables, reports why in its status and log, and never drinks an unverified item; the rest of RealmTool keeps working. Pinned in Tasks 5 and 7.

  ```ts
  export type Capability = 'packets' | 'commands' | 'notifications' | 'inject' | 'worker';
  export interface WorkerChannel {
    /** Module-wide configuration for this plugin's worker module (module id = plugin id). Coalesced: while the host is starting or applying a profile only the last value per plugin is kept, and all plugins' values are sent in one batch. */
    configure(config: unknown): void;
    /** A message for this plugin's worker module instance on one game connection. Ignored when that client is no longer connected. */
    send(client: ClientConnection, message: unknown): void;
    /** Session messages from the worker module. Delivered while the plugin is disabled (status keeps flowing); removed on cleanup. */
    onMessage(handler: (client: ClientConnection, message: unknown) => void): void;
  }
  PluginContext.worker: WorkerChannel; // getter; throws without the 'worker' capability, like other gated members
  export type ProxyLike = Pick<ProxyHost, 'on' | 'off' | 'setInterest' | 'forward' | 'inject' | 'configureModules' | 'moduleCommand'>;
  // pluginHarness: FakeProxy records configured: Record<string, unknown>[] (one entry per configureModules call) and commands: { moduleId, id, message }[];
  // harness.workerMessage(id: string, moduleId: string, message: unknown): void  emits a 'module' event.
  ```

  3. `send(client, msg)` calls `moduleCommand(pluginId, client.clientId, msg)`; after the client closed, nothing is sent.
