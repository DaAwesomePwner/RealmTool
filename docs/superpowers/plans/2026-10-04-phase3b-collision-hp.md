# RealmTool Phase 3b — Auto Nexus Collision HP (default ON)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Auto Nexus estimates HP from the game client's own collision reports (`PLAYERHIT`, `AOEACK`, `GROUNDDAMAGE`), assessed synchronously in the network worker before the report is forwarded, with server HP as the authoritative floor. Collision HP is **ON by default** and is the last functional gate before the release UI (design §5).

**Architecture:** Port realm-engine-client's active reported-impact model (`HealthPredictor`, `DamageModel` and the ON branches of `SafetyEngine`) into the 3a safety core, not its retired native-forecast subsystem. The worker transport gains three narrow capabilities that the source worker had and RealmTool lacks:
- a pending-delivery view (stalled-delivery fail-safe);
- a final pre-RC4 preparation hook with observation identity (injected and rewritten reports);
- a guard recheck right after observation (the crossing report is never forwarded).

Projectile and damaging-tile metadata come from a generated, build-stamped `data/catalogs/safety.json` of compact tuple rows. The runtime never parses XML. The Auto Nexus facade adds the saved `PreHitPrediction` setting (default true), a catalog build check, and status/notification text.

**Tech Stack:** Same as Phases 1–3a (Node ≥ 22.18 native TypeScript, Vitest 3, `fast-xml-parser` dev-only under `tools/`). No new dependencies.

**Spec:** [`docs/design.md`](../../design.md) §2.1, §2.3, §3 items 1–6 and "Hit model", §5 row 3b. Port research: [`docs/research/07-phase3b-port-details.md`](../../research/07-phase3b-port-details.md), cited as **R§n**; its **Addendum** has the measured catalog numbers. Phase 3a context: [`docs/handoff/2026-10-04-phase3a-handoff.md`](../../handoff/2026-10-04-phase3a-handoff.md), [`docs/research/06-phase3a-port-details.md`](../../research/06-phase3a-port-details.md). ## Global Constraints

- All Phase 1–3a constraints still apply:
  - `.ts` import specifiers, erasable syntax only (no enums, namespaces or constructor parameter properties);
  - `npm run check` green; Windows x64; listen only on 127.0.0.1;
  - RC4 keys only in `src/protocol/constants.ts`; never start `RotMG Exalt.exe` directly;
  - the game access token is never logged, persisted or kept beyond the call that uses it.
- Ported files keep `// Ported from realm-engine-client <path> @ 88a66b2 (MIT, see NOTICE).` (or `// Adapted from …` when changed beyond imports/syntax).
- **Time-critical decisions run only in worker modules.** Prediction, the threshold check and the ESCAPE write happen in the worker, synchronously on receipt of the report, before the report is enqueued, forwarded or posted to the main thread. Nothing on that path waits on the main thread.
- **Collision HP default ON.** The saved key is `PreHitPrediction` (label "Collision HP"). It is true for new profiles, empty settings and 3a profiles (no key); an explicit `false` is respected. `safetySettings({})` normalizes a missing value to `true`.
- **Threshold:** HP threshold = `maxHp * thresholdPct / 100`, unrounded, with maxHP from stat **0** only. ON triggers on `lowerHp <= threshold`, where `lowerHp = max(0, serverHp − remaining assessed loss)`. **0% triggers only on an explicit server HP of 0, in both modes, and requires a known positive maxHP** (ruling R5). Unknown HP with no pending loss never triggers.
- **Loss model** (R§1): `assessPredictedLoss` exactly as REC. Unknown identity, definition, piercing metadata, conditions, DEF, or `%`-HP damage → `max(200, validRaw ? raw : 0)` labelled `assumed`. Mitigated hits use `max(trunc(raw/10), raw − effectiveDEF)` with Armored/Armor Broken/Exposed/Curse exactly as REC. Estimates are labelled estimates, never bounds.
- **Server DAMAGE never double-charges** a reported projectile, in either arrival order, including a measured 0 (design §3 item 2).
- **Escape and guard unchanged from 3a:** normal ESCAPE plus server-authorized RECONNECT; initial write plus up to 4 retries 400 ms apart; report guard after an accepted **automatic** escape only, checked at entry (now also immediately after observation) and at the final writer; only a new upstream TCP generation releases it.
- **Stalled delivery** (design §3 item 3): applies only while remaining assessed loss is > 0 (ruling R3), excludes frames a plugin has dropped, and fires after 100 ms (`min(100, reactionMs/4)`).
- **Catalog:** `data/catalogs/safety.json` is generated by `tools/gen-catalogs.ts`, stamped with the Unity `build-guid`, compact JSON with tuple rows, and must stay **≤ 1 MiB** (measured 377 KB; consumables + safety ≤ 2 MiB, design §1). The runtime validates and never parses XML.
- No native-health, forecast, telemetry, reaction-learning, recorder, dashboard or status-relay code, and no `DamageLedger` debt engine (R§2, ruling R7). The coordinator's write-receipt callback stays (the guard needs it).
- Messages and docs never describe report suppression or Collision HP as survival protection (design §3 "Hit model").

## Rulings for this phase (the controller's; R2 decided by the user on 2026-10-04)

Each ruling ends with what it costs if it turns out wrong.

- **R1 Default ON.** Default ON for new profiles, empty settings and 3a profiles; explicit OFF respected; no migration flag needed (3a never saved the key). *Cost:* none.
- **R2 Server-HP fallback for a missing, invalid, unknown-build or mismatched safety catalog** (the user's ruling, 2026-10-04, replacing the proposed "degraded ON"). Collision HP is suspended and Auto Nexus runs server-HP-only, behaving exactly as with Collision HP OFF, until a valid catalog for the installed build is in use. The engine never sees stale metadata.
  - The saved `PreHitPrediction` is never changed by a fallback (never saved as false).
  - The worker reports the **effective** mode as `collisionHp: 'on' | 'off' | 'fallback'`. `fallback` means the setting is ON but no usable catalog exists.
  - **The fallback must be obvious:**
    - a load-log warning;
    - one in-game notification per new game connection while in fallback: `Collision HP FALLBACK: server HP only (<reason>). Run npm run gen:catalogs and restart RealmTool.`;
    - `/an` and the decision notification say `Collision HP fallback (server HP only)` plus the reason, never plain "on" or "off".
  - When a later build check passes (on `clientConnected` or enable), prediction resumes.
  - Entering or leaving fallback is a mode change: prediction debt is retired and the server HP anchor kept (R11).
  - *Cost:* after a game update, Auto Nexus reacts only to server HP (later than Collision HP would) until `npm run gen:catalogs` and a restart.
- **R3 `deliveryStalled` requires remaining assessed loss > 0.** REC uses the pending entry *count*, which includes zero or fully credited entries (R§8.4). *Cost:* a divergence from REC, pinned by a test.
- **R4 Unresolved-report occurrence numbers come from a monotonic per-epoch serial.** They never restart after REC's 12 s window, so they can't collide with an older unresolved id that still carries debt (R§8.5). *Cost:* none expected.
- **R5 Zero threshold:** explicit server zero and a known positive maxHP in both modes. REC's ON branch skips the maxHP check (R§8.8). *Cost:* none.
- **R6 SERVERPLAYERSHOOT is not tracked** (parity); unmatched reports take the unknown path (R§8.12). *Cost:* hits from those sources are assumed at `max(200, raw)`.
- **R7 No DamageLedger.** `HealthPredictor` is the only debt engine; RT's nullable `lastHp` stays the server anchor (R§1). *Cost:* none.
- **R8 Catalog format** (Addendum):
  - Compact tuple rows. Object/tile types are parsed as hex (`0x…`) or decimal, never forced hex. Identical duplicates collapse; a conflicting duplicate fails generation.
  - Bounds: types 0…65535; projectile ids 0…255; `lifetimeMs` 0…10⁹; effect `durationSec` 0…10⁶ (real max 100,000); damage and `maxHealthDamage` 0…10⁶.
  - *Cost:* a future game value outside these bounds fails generation visibly, with a message.
- **R9 AoE queue:** FIFO as REC (an AOEACK consumes the oldest area). Cleanup additionally drops areas older than 10 s; such areas could never be "known" (known requires age ≤ `max(1000, 2·reactionMs)`). *Cost:* none expected; pinned by a test.
- **R10 Client reports that survive an upstream generation change** are assessed afresh at final preparation in the new epoch, never delivered against the old model.
- **R11 A held report final-written after a Collision HP toggle** is a fresh assessment in the new mode. Debt from before an intentional mode change is retired (REC).
- **R12 Same-GUID game updates stay undetected** (3a ruling 4 still applies). The catalog keeps source SHA-256 hashes for diagnosis only.

## Review Focus

1. **The main thread is stalled (slow plugin hook, GC) while a PLAYERHIT crosses the predicted threshold.** The worker writes ESCAPE on that report. The triggering report is never written upstream, and nothing reaches the main thread before the ESCAPE is written. Pinned in Tasks 6 and 8.
2. **A PLAYERHIT held for a main-thread verdict, then released or dropped.** It is charged exactly once on receipt. Released: its delivery age starts at its actual write. Dropped: its loss is kept, but its delivery association is not. Pinned in Tasks 2 and 6.
3. **Server DAMAGE for a reported projectile arrives before or after the PLAYERHIT, including a measured 0.** It is charged once. Repeated unknown or multi-hit reports are never forgiven by one DAMAGE. Pinned in Task 5.
4. **The safety catalog is missing, corrupt, overridden by a bad file, or from another build.** Auto Nexus falls back to server HP only with no stale metadata (R2), the fallback is obvious in chat, status and logs, and Auto Drink and the rest of RealmTool keep working. Pinned in Tasks 4, 6 and 7.
5. **A 3a profile is upgraded, or Collision HP is toggled mid-fight.** Upgrading gives ON; an explicit OFF stays OFF. Toggling retires prediction debt but keeps server HP, its age and the escape lifecycle, and never creates healing. Pinned in Tasks 5 and 7.

  ```ts
  /** A frame accepted from a socket and not yet written or dropped (the stalled-delivery view). */
  export interface PendingDelivery {
    readonly observationId: number;
    readonly name: string;
    readonly fromClient: boolean;
    /** Same clock as WorkerSessionContext.now(). */
    readonly receivedAt: number;
    readonly generation: number;
    /** awaiting: a main-thread verdict is outstanding. ready: passed (or needed no verdict) but blocked behind earlier frames. */
    readonly state: 'awaiting' | 'ready';
  }
  WorkerSessionContext.pendingDelivery(): readonly PendingDelivery[]; // oldest first; excludes verdict-dropped frames at once and other generations' server frames
  /** A client→server frame named in the module's `prepare` list, about to be encrypted and written. */
  export interface PreparedWrite {
    /** Session-unique; exactly one writeOutcome follows for each module that received prepareWrite. */
    readonly token: number;
    /** The final frame as it will be written (after plugin replacement). */
    readonly packet: Packet;
    readonly kind: WriteKind;
    readonly now: number;
    /** The original observation when this is that frame's same-named release; null for injected, priority, renamed or pre-connect-queued frames. */
    readonly observationId: number | null;
    readonly origin: string | null;
  }
  WorkerModule.prepare?: readonly string[];
  /** Before module vetoes and output RC4. May write priority frames reentrantly (e.g. ESCAPE). */
  WorkerSessionModule.prepareWrite?(write: PreparedWrite): void;
  /** accepted = the socket writer took the frame; false = vetoed, malformed, socket gone, or session closed. */
  WorkerSessionModule.writeOutcome?(token: number, accepted: boolean, now: number): void;
  // changed signature (observationId appended; existing implementers ignore it):
  WorkerSessionModule.writtenServer?(packet: Packet, kind: WriteKind, now: number, observationId: number | null): void;
  ```
- **Session behavior** (R§3 "Mapping onto RT", items 3–6):
  1. **Post-observe guard:** in `accept`, after all `observe` hooks, ask every module's `suppressEntry(name, fromClient)` again. If any says true, call `notifyDropped` for that observation once and return. The frame isn't enqueued, posted to the main thread, or written.
  2. **pendingDelivery:** built from `this.pending`. `result === undefined` → `awaiting`; a Buffer → `ready`; `null` → excluded. Server frames of another generation are excluded.
  3. **Write order for a client→server frame:** whole-frame check → pre-connect queueing (`!serverReady`; the queued frame is re-written later through the same path) → `prepareWrite` for modules whose `prepare` names it, in priority order (one token per frame) → `allowWrite` vetoes → `writeRaw` → `writeOutcome(token, accepted)` to every prepared module → `written`. Every exit after preparation (veto, `writeRaw` false, closed) sends `writeOutcome(token, false)`. `observationId` is the original's id only when `name === observation.name`. A renamed frame's original gets `dropped` **before** preparation of the replacement.
  4. Server-direction writes are unchanged except that `writtenServer` receives the observation id (null for injected/priority).
  5. `call()` isolation applies to the new hooks; a throwing `prepareWrite` counts as prepared (it still gets an outcome).
